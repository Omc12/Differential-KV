## 2. Architecture (reconstructed from current code)
Model under test: Qwen2.5-1.5B-Instruct, MLX int4 — L=28, H=12, H_kv=2 (GQA G=6), d=128.
Hyper-params (bench config): block B=256, rank r=16, recency W=512, dense buffer D_max=W+B=768,
max_blocks M=256 (→ 64k compressed-addressable tokens), max_residual R=64.

Per-session state, per layer:
- Dense recency window: K,V fp16 [H_kv, D_max, d] (sliding, exact).
- Compressed pool (pre-allocated M blocks): U[B-1,r], V_K/V_V[H_kv,r,d], anchor_k/v[H_kv,d],
  min_k/max_k[H_kv,d] (router), scale, seq_len, AND res_k/res_v[R,H_kv,d] (exact residuals).

Compression (`_compress_block`): per block → anchor = token 0; deltas vs anchor; row-L2-normalize;
randomized truncated SVD (NumPy, fixed seed 1234), adaptive rank (99.9% energy, clamp [4,16]);
re-apply norms. THEN residual correction: reconstruct, measure per-token error, keep the
**top-64 highest-error tokens as EXACT fp16 K/V residuals** (the needle's distinctive tokens are
the highest-error ones SVD truncates). Stored highest-error-first.

Decode (`execute_decode_attention` + `compute_decode_attention_static`, `@mx.compile`):
1. Top-K block routing (K=16, `residual` router): rank blocks by exact q·k over anchor + R
   residual keys; select top-K. (`minmax` Quest router available, looser.)
2. Low-rank branch: score query in SVD subspace → per-token scores without decompressing KV.
3. Exact branch: selected blocks' residual K/V are **concatenated with the recency window** →
   exact attention.
4. Flash-style LSE merge of low-rank + exact branches.
Cost scales with K, not context → ~flat decode cost at large ctx.

Decode policy (`_resolve_compressed_decode`): **auto** (default), threshold
`DIFFKV_COMPRESSED_MIN_CTX=16384`. <16k → exact full-KV decode (faster, memory-safe);
≥16k → compressed sparse decode (bounded decode-time footprint). Decided once at the
prefill→decode boundary, where the native prefill KV cache is dropped + peak released.

## 3. Data-integrity findings (THE reason prior data was "wrong")
- **F1 — prior sweep is pre-fix.** `paper/generated/active_modes_sweep.json` (06-28) shows
  compressed mode `needle_found:false` at every ctx (garbled "OP-123","Omega","O9999…"). That is
  the state BEFORE the 06-29 fix (max_residual 32→64 + residual-key router). **Do not reuse it.**
- **F2 — compression ratio was overstated ~3.5×.** Old note/sweep `per_block=25,576 B → 10.25×`
  OMITTED the residual (65,536 B) and min/max (1,024 B) buffers. Verified against the live manager:
  true per-block = **92,136 B → 2.845×** (dense block 262,144 B). Asymptote ~2.85× as compressed
  blocks dominate; ~1× at short ctx (dense window dominates). Pre-alloc bounded pool = 0.682 GB.
  Fixed in `paper/scripts/measure_active.py::analytic_kv_bytes`.
- **F3 — REPORT.md "active" (45→17 tps) is the EXACT path**, not compressed (prior conflict,
  already resolved). Treat exact decode as an upper-bound ablation, not the headline.
- **F4 — memory headline must be precise.** MLX allocator peak (`mx_peak`) is prefill-dominated and
  ≈ between active/dense at matched ctx (active slightly higher: compression scratch). The genuine
  win is (a) bounded decode-phase footprint (`mx_decode_peak`), (b) analytic store bytes, (c)
  **context reach**: dense crashes @32k (RAM cap/swap) while active completes 32k and reaches 64k.
  Process-tree `max(phys,RSS)` is noisy → secondary/appendix.
