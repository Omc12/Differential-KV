## 1. What the implementation actually is (source of truth)
- Live engine on Mac: `serving/mlx_diffkv_wrapper.py`. `DiffKVHFWrapper` is rebound to
  `MLXDiffKVWrapper` on macOS+MLX (`hf_diffkv_wrapper.py:1221-1223`), so every "active"
  benchmark = the MLX runtime. SRL/factual/eagle subsystems are OFF by default
  (`DIFFKV_FACTUAL_STORE=0`), so they are NOT part of the paper's evaluated system.
- Compression (`compress_deferred_prefill_blocks`, L1457): block=256 tokens; anchor=token 0
  kept exact; joint K|V deltas row-normalized; V rescaled to K's RMS (`DIFFKV_V_SCALE`);
  randomized truncated SVD (seed 1234, adaptive rank ≤ `rank`, 99.9% energy) → U, V_K, V_V;
  top-`max_residual` highest-joint-error tokens kept EXACT (res_k/res_v); per-block key
  min/max stored for the router. Batched across layers×blocks (one GPU SVD).
- Decode (`compute_decode_attention_static`, L305): sparse half (routed blocks, scored in
  low-rank space: anchor score + (q·V_K)·Uᵀ, never decompressing K) ⊕ dense recency window,
  combined by a flash-style LSE merge. Residual tokens attended EXACTLY in the dense half;
  their lossy low-rank twins masked out (`DIFFKV_RESIDUAL_EXCLUDE_SVD`). Top-K routing
  (`_block_relevance_residual`, default K=16) bounds cost to O(K), not O(context).
- Shipping defaults (constructor): rank=16 (CLI/bench), block_size=256, recency_window=512
  (dense window = recency+block = 768), max_blocks=256 (bounded pool → 64k), max_residual=128,
  topk_blocks=16, router=residual, DIFFKV_COMPRESSED_DECODE=1, DIFFKV_SPARSE_PREFILL=1 (ON),
  DIFFKV_DECODE_CACHE=0.

## 3. CORRECTIONS vs the old (2026-06-30) paper — these are why the old data was "wrong"
1. **RETRACT "dense OOMs by 32k."** Dataset B shows dense completing to 64k (5.89 GB, 15.6
   tps) because bench_worker now releases prefill peak at the prefill→decode boundary. So on
   this 8.6 GB machine, dense REACHES 64k. Do not claim DiffKV uniquely reaches long context.
2. **Compression ratio is config-dependent.** Per-block: maxres=64 → 2.845×; **maxres=128
   (shipping default) → 1.66×**. Report both; the residual sweep is the bridge. The 10.25×
   (low-rank only) is wrong accounting (omits residuals) — keep only as the corrected figure.
3. **Memory is a wash on allocator peak at this scale.** active mx_peak ≥ dense at 32k–64k
   (residual pool + dense window + compressed pool). The honest memory claim is about the
   ANALYTIC KV-state (bounded, 2–2.8× smaller than full KV), not the measured allocator peak.

## 4. HONEST HEADLINE (what Dataset B actually supports)
DiffKV trades **decode throughput** (3–5× slower than dense decode) for:
(a) a **sparse-prefill speedup that crosses over at long context** — 64k prefill 598.9 s vs
    dense 927.2 s = **1.55× faster**; slightly slower ≤32k (SVD not yet amortized);
(b) a **bounded, 2–2.8× smaller analytic KV-state** (fixed 256-block pool);
(c) **exact retrieval preserved at every context** (needle=Y 4k–64k, both datasets), with the
    residual budget as an explicit accuracy/memory knob.
Framing = "accuracy @ bounded memory + prefill scaling", NOT "faster than dense".
