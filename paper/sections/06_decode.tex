\section{Fused Sparse Decode Attention}
\label{sec:decode}

Decode must produce the attention output a dense cache would, reading only the stored factors and
residuals of \S\ref{sec:compression}. \diffkv{} does this in three stages---route to the relevant
blocks, score/aggregate the low-rank term, and attend the exact residual+recency tokens---then
merges the low-rank and exact branches. Let $q\in\R^{H\times\dhead}$ be the current query (group
query attention replicates the $\Hkv$ KV heads to the $H$ query heads) and $\sigma$ the attention
scale.

\subsection{Top-$K$ block routing}
\label{sec:routing}
At large context the block count $n=N/\bs$ grows, but only a few blocks are relevant to any query.
A router scores every block cheaply and selects the top $\topk$; the expensive low-rank
aggregation and residual attention then run for $\topk$ blocks, not $n$, so decode cost scales with
$\topk$ rather than context. The default \emph{residual-key} router ranks block $b$ by the largest
\emph{exact} query--key score over its anchor and its top-$R$ residual keys,
\begin{equation}
\rho_b = \max\!\Big(\sigma\langle q,\anchork^{(b)}\rangle,\ \max_{j\le R}\sigma\langle q, R_{K,j}^{(b)}\rangle\Big),
\label{eq:router}
\end{equation}
taken over query heads. Unlike a low-rank or min/max \emph{summary} score---both of which average
away the single outlier token a needle is---the residuals \emph{are} the block's distinctive
tokens, so Eq.~\ref{eq:router} is a tight, exact relevance signal that reliably keeps a
needle-bearing block in the top-$\topk$ even at hundreds of blocks. Its cost is $O(nR\dhead)$,
linear in context with a small constant. A cheaper Quest-style~\cite{tang2024quest} key min/max
upper bound is available for short contexts where looseness is harmless; we use the residual
router by default and quantify the difference in \S\ref{sec:eval}. When $n\le\topk$ all blocks are
kept and routing is skipped.

\subsection{Scoring and aggregating the low-rank term}
For each selected block the score of $q$ against a reconstructed key (Eq.~\ref{eq:recon}) factors
through the basis, so we never form the key:
\begin{align}
\text{(anchor)}\quad & s^{\text{anc}}_b = \sigma\, \langle q,\ \anchork^{(b)}\rangle,\\
\text{(project)}\quad & \tilde q_b = \sigma\, q\, V_K^{(b)} \in\R^{\rank},\\
\text{(deltas)}\quad & \delta s_b = s_b\,\big(\tilde q_b\, U_b^{\!\top}\big) + s^{\text{anc}}_b \in\R^{S}.
\end{align}
The middle step projects the query into the block's $\rank$-dimensional key subspace once; the
third recovers the per-token delta scores by a single $\rank{\times}S$ product, at cost
$O(\Hkv\rank\dhead + \rank S)$ per block---\emph{independent of reconstructing the $S{\times}\dhead$
keys}. Tokens beyond a block's valid length are masked to $-\infty$. The per-block scores
$[s^{\text{anc}}_b,\delta s_{b,1},\dots]$ over the selected blocks form one softmax, giving weights
$w$ and a log-sum-exp $\ell^{\text{sp}}$. The output is assembled from the same factors,
\begin{equation}
O^{\text{sp}} = \underbrace{\sum_b \big(w^{\text{anc}}_b + \textstyle\sum_i w^{d}_{b,i}\big)\,\anchorv^{(b)}}_{\text{anchor value mass}}
 \;+\; \underbrace{\sum_b s_b\,\big(w^{d}_b\, U_b\big)\,V_V^{(b)}}_{\text{delta value mass}},
\end{equation}
contracting the delta weights through the same $U$ and then the value basis $V_V$---again never
forming dense values.

\subsection{Exact residual + recency branch}
The selected blocks' exact residual tokens $\{R_K^{(b)},R_V^{(b)}\}$ are gathered and
\emph{concatenated with the dense recency window} into an augmented exact set $(\tilde K,\tilde V)$,
over which standard attention is computed to give $O^{\text{dn}}$ and $\ell^{\text{dn}}$. This is
the branch that preserves verbatim detail: a needle token, captured as a residual during
compression (\S\ref{sec:residuals}), is attended here at full fp16 precision rather than through
the lossy low-rank term. The augmented width is padded to a bucketed capacity (multiples of $256$)
so the compiled kernel recompiles only when crossing a bucket, while the attention width tracks the
real token count rather than the worst-case $\maxres\cdot M$.

\subsection{Stable two-branch merge}
The low-rank and exact branches are combined by a flash-style log-sum-exp reduction,
\begin{equation}
m=\max(\ell^{\text{sp}},\ell^{\text{dn}}),\quad
O = \frac{e^{\ell^{\text{sp}}-m}O^{\text{sp}} + e^{\ell^{\text{dn}}-m}O^{\text{dn}}}
        {e^{\ell^{\text{sp}}-m} + e^{\ell^{\text{dn}}-m}}.
\end{equation}
This is the standard log-sum-exp combination of two softmax partitions, correct only if a
\emph{fully masked} branch contributes exactly zero weight. When there are no compressed blocks yet
the kernel takes a dense-only fast path; otherwise it sanitizes each branch's log-sum-exp and output
to a finite, fully-down-weighted value before the merge, so an empty compressed set cannot poison the
result with NaNs---a guard the source documents as a real bug fix and we retain verbatim.

\begin{algorithm}[t]
\caption{\textsc{FusedDecodeAttention} (one token, one layer)}
\label{alg:decode}
\begin{algorithmic}[1]
\Require query $q$; pool $\{U,V_K,V_V,\anchork,\anchorv,s,R_K,R_V\}_{1:n}$; window $K^{\text{win}},V^{\text{win}}$; top-$K$ $\topk$
\State ingest current token's $(K,V)$ into the window \Comment{attend to self}
\If{$n>\topk$} $\mathcal{S}\gets$ top-$\topk$ blocks by $\rho_b$ (Eq.~\ref{eq:router}) \Comment{router}
\Else\ $\mathcal{S}\gets\{1{:}n\}$ \EndIf
\For{each block $b\in\mathcal{S}$}
  \State $s^{\text{anc}}_b\gets\sigma\langle q,\anchork^{(b)}\rangle$;\ \ $\tilde q_b\gets\sigma\,qV_K^{(b)}$;\ \ $\delta s_b\gets s_b(\tilde q_b U_b^{\!\top})+s^{\text{anc}}_b$
\EndFor
\State $w,\ell^{\text{sp}}\gets\softmax,\lse$ over $\mathcal{S}$;\ \ $O^{\text{sp}}\gets$ anchor + delta value mass
\State $(\tilde K,\tilde V)\gets \textsc{Concat}(\{R_K^{(b)},R_V^{(b)}\}_{b\in\mathcal{S}},\,K^{\text{win}},V^{\text{win}})$
\State $O^{\text{dn}},\ell^{\text{dn}}\gets \textsc{ExactAttn}(q,\tilde K,\tilde V)$
\State sanitize NaN/$\infty$;\ \ \Return flash-merge$(O^{\text{sp}},\ell^{\text{sp}},O^{\text{dn}},\ell^{\text{dn}})$
\end{algorithmic}
\end{algorithm}

\subsection{Compute profile}
Per token the kernel does $O(nR\dhead)$ for routing, $O\!\big(\topk(\Hkv\rank\dhead+\rank\bs)\big)$
for the low-rank term over the selected blocks, and $O(\Hkv(\topk\maxres+\dwin)\dhead)$ for the
exact branch. With $\topk$ fixed, the low-rank and exact work are \emph{context-independent}; only
the router is linear in context, with a small $R\dhead$ constant. The result is a decode cost that
is nearly flat in context (\S\ref{sec:eval})---the asymptotically attractive property---but whose
absolute throughput is set by the many small tensor ops the kernel issues inside one compiled
graph. On the test hardware these do not yet match MLX's native fused attention over a contiguous
cache; \S\ref{sec:eval} quantifies the gap and \S\ref{sec:limitations} discusses the hand-written
fused kernel (a custom Metal op, or CUDA/Triton) that is the natural way to close it.
