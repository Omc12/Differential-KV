\section{Conclusion}
\label{sec:conclusion}

\diffkv{} treats the KV cache as a structured object rather than an opaque tensor: each block is a
representative anchor, a low-rank correction, and a small set of exact residual tokens, and
attention is computed directly from that representation without ever rebuilding the dense cache.
The low-rank term and a bounded pool give a KV state that is fixed and context-independent; the
residuals give back the verbatim recall that pure low-rank compression loses. The payoff is that a
small model addresses contexts that exhaust a full-KV baseline on the same $8$\,GB device, while
recovering a buried passcode exactly at every context we test. We have been explicit about the
costs measured on the way there: the compressed decode is slower than dense decode on current
hardware---a kernel-dispatch gap we localize precisely with an exact-decode ablation on the
identical store---the exact recall is bought with the memory the residuals occupy
($\approx\!2.85\times$ reduction, not an order of magnitude), and the per-block SVD makes prefill
the slowest phase. We report the compressed path as the primary result and the exact path only as
an upper bound, attributing every number to the code that produced it.

The most valuable next steps are sharp and already scoped: a hand-written fused decode kernel to
close the throughput gap, a content-adaptive residual budget to improve the compression ratio and
push past the residual memory ceiling at extreme context, and a CUDA/Triton implementation whose
results can drop into the existing figures unchanged. The design---anchor plus differential
low-rank plus exact residuals, attention routed and computed in low-rank space, a bounded pool with
a recency window and an adaptive decode policy---stands independent of those refinements, and the
runtime that realizes it is small, composes with stock quantized models, and runs on the hardware
people already have.
