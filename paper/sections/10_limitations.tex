\section{Limitations and Future Work}
\label{sec:limitations}

\paragraph{Single-token recall fidelity (primary).}
As \S\ref{sec:fidelity} shows, rank-$16$ compression does not preserve enough of a single
buried token for verbatim recall after it leaves the recency window. The most direct remedies,
all present in spirit elsewhere in the codebase, are: (i) a higher or per-layer-adaptive rank;
(ii) an \emph{exact-token residual} path that stores a small fraction of high-error tokens
losslessly alongside the low-rank term; and (iii) keeping known-important spans in the dense
window. Quantifying the rank/fidelity and residual-budget/fidelity trade-offs is the most
important next experiment.

\paragraph{Determinism.}
The randomized range finder is unseeded, so the compressed path is run-to-run
non-deterministic. A fixed seed (or an exact small-block SVD) should be adopted before any
fidelity study so results are reproducible to the bit.

\paragraph{Decode throughput.}
The fused kernel is expressed as many small ops in a compiled graph and does not yet match
native fused attention (\S\ref{sec:analysis}). A hand-written fused decode---a custom Metal op,
or a CUDA/Triton kernel on NVIDIA hardware---is the natural path to closing the gap. We have
deliberately structured the throughput figures and the main results table so that a future
\textbf{CUDA/Triton fused-decode} measurement can be added as one more series without
restructuring the evaluation; no such number is reported or estimated here, and the placeholder
is labelled as future work.

\paragraph{Evaluation breadth.}
We report one model (Qwen2.5-1.5B int4), one device (Apple~M3, $8.6$\,GB), and one probe
(needle-in-a-haystack) with greedy decoding. Broader claims require additional models and sizes,
perplexity and downstream-quality metrics beyond exact-string recall, and batched/multi-session
throughput. The serving stack supports batching and multi-session residency; we did not exercise
them here.

\paragraph{Prefill cost and peak.}
Prefill remains exact and therefore $O(N)$ in attention, and the global memory peak is set during
prefill (\S\ref{sec:analysis}); \diffkv{} does not reduce that peak. Compressed or sparse prefill
is a known direction (prototyped in the repository) but is out of scope here.

\paragraph{The grounding module.}
The semantic-retrieval/factual-binding layer is inactive in the benchmarked runtime
(\S\ref{sec:impl}). Whether it improves grounded long-context QA on top of the compressed cache
is an open, separately evaluable question.

\paragraph{Portability.}
The runtime is specialized to MLX and to the Qwen2 attention module it patches. The portable
PyTorch/Triton backend in the repository targets the same design but is under active development
and is not evaluated here.
