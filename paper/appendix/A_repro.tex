\section{Reproducibility}
\label{app:repro}

All results were produced on a single machine, one engine per isolated subprocess, with every
number measured (failed cells are reported as failures, never filled with estimates).

\paragraph{Hardware.}
Apple~M3, $8.6$\,GB unified memory, macOS (Darwin~25.x). The device is shared with the OS and
other applications, so absolute memory thresholds and long-context prefill times shift with
machine load; the scaling slopes, engine ordering, and exact-recall results are the stable
outcomes.

\begin{sloppypar}
\paragraph{Software.}
Python in \texttt{dkv\_venv}, MLX~$0.31.2$, \texttt{mlx\_lm}, NumPy~$2.x$,
PyTorch (used only for tensor plumbing in the wrapper, not for compute),
\texttt{psutil}. Model: \path{mlx-community/Qwen2.5-1.5B-Instruct-4bit}
(group size $64$, $4$-bit), $28$ layers, $12$ query heads, $2$ KV heads, head
dim $128$, trained context $32{,}768$, RoPE $\theta=10^6$.
\end{sloppypar}

\begin{sloppypar}
\paragraph{Configuration (as measured).}
preset \texttt{mid}, \texttt{serving\_mode=balanced}, \texttt{rank=32} (the ``mid'' preset
default; only the ``low'' preset reduces it to $16$), \texttt{block\_size=256},
\texttt{recency\_window=1024} (dense buffer $\dwin{+}\bs=1{,}280$), \texttt{max\_blocks=256},
\texttt{max\_residual=128}, top-$K{=}16$ routing with the \texttt{residual} router,
\texttt{DKV\_SVD\_SEED=1234} (deterministic). The \dkv{} engine runs in
the active CLI's serving configuration with the sparse path forced on at every
context: \texttt{DKV\_COMPRESSED\_DECODE=1} (so DKV's compressed decode is
what is measured at all lengths, not the adaptive dense-below-threshold policy),
\texttt{DKV\_DECODE\_FUSED=1} (persistent fused-buffer decode, default on;
\texttt{DKV\_DECODE\_CACHE} is \emph{off} by default since Jul 2026 and was not
used in the reported measurements),
\texttt{DKV\_SPARSE\_PREFILL=1} (block-sparse prefill),
\texttt{DKV\_SPARSE\_BIAS=auto} (adaptive merge bias, as the CLI ships).
The optimized dense baseline is \texttt{mlx\_lm} with a full KV cache on the same
int4 weights. The standard PyTorch baseline is \texttt{AutoModelForCausalLM} on
\path{Qwen/Qwen2.5-1.5B-Instruct} with \texttt{torch\_dtype=float16} on the MPS
backend---unquantized weights, since \texttt{transformers} cannot load the MLX
int4 checkpoint---and is therefore a practitioner-default reference rather than a
weight-matched control (\S\ref{sec:eval}).
The residual sweep (E5) forces \texttt{DKV\_COMPRESSED\_DECODE=1}
and varies \texttt{DKV\_MAX\_RESIDUAL}; the decode-mode ablation (E6) toggles
\texttt{DKV\_COMPRESSED\_DECODE} between $1$ (compressed) and $0$ (exact
upper bound) over the same store.
\end{sloppypar}

\paragraph{Protocol.}
A needle-in-a-haystack chat prompt is built once per context length from the Qwen2.5 tokenizer and
fed verbatim (raw mode, no double chat-templating) to every configuration. The needle is a planted
passcode (\texttt{OMEGA-7741-DELTA}); ``needle recovered'' means the generation reproduced it.
Engines are warmed once (a $1$-token forward to compile kernels) before timing. Prefill is timed
with \texttt{perf\_counter} around the chunked forward after \texttt{mx.eval}; decode is
fixed-length greedy ($128$ tokens, EOS ignored) so throughput is directly comparable. Memory is
read from MLX's allocator (\texttt{get\_peak\_memory}) for the two \mlxe{} engines and from
\texttt{torch.mps.driver\_allocated\_memory()} for the PyTorch engine---different metrics, not
interchangeable. Each \texttt{(engine, context)} cell runs
in its own subprocess so memory is attributable and an out-of-memory event kills only that cell.
The full primary sweep is a single back-to-back batch, so \dkv{} and the optimized dense engine are
measured under the same machine conditions; the volatile long-context dense cells were re-measured
in isolation to confirm their regime. The PyTorch cells come from a separate worker
(\path{benchmarks/bench_worker.py}), which does not synchronise the MPS queue before stopping its
prefill timer---see the caveat in \S\ref{sec:eval}.

\begin{sloppypar}
\paragraph{Artifacts and provenance.}
Primary measured JSON: \path{benchmarks/results/clean_{active,dense,normal_dense}_{ctx}.json}.
Ablations: \path{paper/generated/active_modes_fresh.json} (decode modes) and
\path{paper/generated/residual_sweep_fresh.json} (residual budget); as noted in
\S\ref{sec:eval}, these two were collected in earlier runs under a different
decode-path configuration, so their absolute throughput is not comparable to the
primary sweep. Tables~\ref{tab:config}--\ref{tab:ablation} and every data figure
are regenerated from these files by the scripts above, and the body text's numbers
are LaTeX macros emitted by \texttt{make\_facts.py}, so that prose cannot drift
from that data.

\emph{Provenance gap.} The E7--E12 tables (multi-needle, Llama-3.2-3B, the residual-signal
ablation, and lego prefill) are transcribed by hand rather than generated: their harnesses are
\path{benchmarks/run_multi_needle_mlx.py}, \path{run_llama3b_mlx.py},
\path{run_signal_ablation_mlx.py} and \path{run_lego_mem_mlx.py}, but the result JSONs those
scripts emit are not checked into this repository, so those four tables are not machine-verifiable
from the artifact the way Tables~\ref{tab:config}--\ref{tab:ablation} are. Re-running the listed
harnesses regenerates them. The dataset selection, the decode-path attribution that motivated this
measurement design, and the corrected compression-ratio accounting are documented in
\path{paper/notes/AUDIT_2026-07-07.md}.
\end{sloppypar}
